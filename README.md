# ai-template

開発エージェントが対話を通じてプロジェクトの開発環境を整えるための手順書です。利用者は初期化したいディレクトリを開き、次のように依頼してください。

> この target-project を https://github.com/Taiki2523/ai-template のREADMEに従って初期化してください。

以下は依頼を受けたエージェントへの指示です。作業先は利用者が開いた target-project です。このガイドをリモートで参照し、生成物と依存ツールは対象プロジェクトに配置してください。

## 1. 対象を確認する

作業ディレクトリ、Git状態、README、既存設定、言語・依存管理ファイルを読み、既に決まっていることを短く整理する。作業先が曖昧な場合は確認する。既存プロジェクトでは利用者の変更を保つ。

## 2. 必要な環境を聞く

ファイル作成やダウンロードに着手する前に、調査で分からなかったことを質問する。最初の質問は次の三点を目安に、一度に答えやすい量にする。

- 誰が何に使うプロジェクトか。最初に動かしたいものは何か。
- 使いたい言語、フレームワーク、依存管理ツール、実行環境はあるか。
- 起動・テスト・整形・CIのうち、初日から使いたいものは何か。チームや配布先の制約はあるか。

未定の項目は目的に合う候補と理由を示して一緒に決める。例えば「ローカルで使うPython CLI」なら、ブラウザやデプロイ先の質問を省いて、実行方法と入出力例を聞く。

## 3. 作成内容を合意する

回答をもとに、作成・更新するファイル、取得するツールと取得元、実行コマンド、完了を判断する動作例を提示する。既存ファイルとの競合は具体的な差分で示す。合意した構成を以降の作業基準にする。

## 4. 対象プロジェクトでセットアップする

必要なディレクトリ、依存定義、最小の起動入口、合意したテスト・設定を作る。選んだツールの公式配布元やパッケージ管理機構を使って依存を取得し、対象プロジェクトの慣例に沿って版を記録する。プロジェクト用READMEには起動・検証手順を残す。Spec Kit、エージェント向け規約、CI、追加ハーネスはヒアリングで必要と判断したものを導入する。

## 5. 実際に動かして引き渡す

対象ディレクトリで合意した動作例とテストを実行する。失敗したら原因を調べ、合意範囲で修正して再実行する。再度初期化を依頼された場合は現在の状態と希望の差分だけを適用する。

最後に、作業先、採用技術、作成・更新したファイル、実行した検証と結果、利用者が次に打つコマンドを報告する。権限や外部設定の都合で未実行の項目は理由を添える。
